# 설명 질문과 지도용 예시 답

## 함수

`calculate_amount(3000, 2)`에서 3000과 2가 매개변수에 들어가고 6000이 반환됩니다.
print만 하면 화면에 6000이 보일 수 있지만 함수의 반환값은 None입니다.
합계 함수의 return이 for 안에 있으면 첫 행을 처리하고 종료합니다.
빈 목록은 반복하지 않으므로 합계 시작값 0을 반환합니다.
심화에서 None은 입력 거절 표시입니다. 수량0의 정상 주문으로 바꾸는 것과 다릅니다.

## 클래스

`self.quantity`는 해당 Order 객체에 저장되는 값입니다. 매개변수 quantity를 속성으로 옮겨 둡니다.
first와 second는 서로 다른 Order이므로 first.quantity를 바꿔도 second의 속성은 그대로입니다.
`amount()`의 괄호는 메서드를 실행한다는 뜻입니다. 금액을 얻으려면 호출해야 합니다.
수량 검증을 먼저 해야 실패한 요청이 기존 객체 상태를 망가뜨리지 않습니다.
Cart의 목록은 __init__ 안에 두어 객체마다 새로 만듭니다. 같은 Order 객체를 넣으면 그 객체의 변경은 반영됩니다.

## 파일

기본필수는 주문 5건, 상품 9개, 금액27000원입니다. 건수와 수량의 분모가 다릅니다.
CSV 숫자는 문자열로 읽히므로 int 변환 후 곱셈·덧셈을 합니다.
JSON은 숫자를 숫자로 읽을 수 있지만 이번 입력 계약에서는 정수 문자열도 허용합니다.
원본 row의 값을 바꾸는 대신 새 Dict를 만들어 출처를 보존합니다.
응용에서 결측 수량을0으로 바꾸면 기록 문제를 정상 거래처럼 보이게 하므로 이유를 별도로 남깁니다.
심화의 중복 ID는 먼저 유효한 행을 임시로 유지합니다. 충돌하는 원본은 확인 대기 목록에 보관합니다.
이 임시 규칙으로 산출한31000원을 최종 실매출이라고 주장하지 않게 합니다.

## 모듈형 프로젝트

storage는 파일, cleaning은 정제, models는 주문 객체, reporting은 집계, main은 전체 순서를 담당합니다.
Dict의 키에는 대괄호, 객체의 속성에는 점을 사용합니다. 금액 메서드에는 괄호까지 붙입니다.
코드를 다른 파일로 나누어도 입력과 반환이 일치하면 같은 기능을 연결할 수 있습니다.
새 파일·클래스를 많이 만드는 것 자체가 좋은 설계의 기준은 아닙니다.
