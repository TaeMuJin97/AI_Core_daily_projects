## 1. Executive Summary

**결론: 기능 검증 PASS / 운영 적용 판단은 보류.** 학습용 이미지 4건에 대한 증강 산출물이 확인되었으며, 저장 성공 기록이 **4/4건(100%)**이고 네 개의 출력 PNG 모두 제공된 기준 이미지와 **바이트 단위로 일치**했다. 처리된 모든 데이터의 `split`은 `train`으로 기록됐다.

| 핵심 지표 | 검증 결과 | 판정 |
|---|---:|---|
| 증강 처리 건수 | **4건** | 기대 건수 충족 |
| 이미지 저장 성공 기록 | **4/4건** | PASS |
| 실제 출력 PNG 존재 및 열기 | **4/4건** | PASS |
| 기준 PNG 바이트 일치 | **4/4건** | PASS |
| 출력 해상도 / 채널 | **320×240 / RGB 3채널** (PNG 디코딩 기준) | 일치 |
| 좌우 반전 적용 | **1건 / 4건 (25%)** | 설정 기록 확인 |
| 밝기 조절 | **증가 2건 / 감소 2건** | 설정 기록 확인 |
| `train` 외 항목의 증강 기록 | **0건** | 산출물 기준 확인 |

> **의사결정:** 현재 증거는 *정상적인 증강 결과 생성과 저장*을 입증한다. **모델 정확도 향상, 데이터셋 적합성, 전체 원본 보존**까지 입증하는 결과는 아니다.

## 2. 목적 및 검증 범위

본 실습은 이미지 분류 학습 파이프라인에서 **학습 데이터에만 데이터 증강**을 적용하고, 증강 설정과 원본 추적 정보를 기록할 수 있는지 확인하는 PoC다.

- **입력/대상:** `manifest.csv`에서 `split=train`인 샘플 (README상 train 4건, valid/test 2건)
- **기법:** 50% 확률 좌우 반전 및 BGR 각 채널에 동일한 밝기 오프셋 `beta∈[-20,20]` 적용
- **안전장치:** `float32` 변환 → 오프셋 적용 → `[0,255]` 클리핑 → `uint8` 복원
- **재현성:** 샘플 ID 기반 고정 난수 Seed, 증강 설정 CSV 및 원본 SHA-256 기록
- **산출물:** `outputs/img_XX_aug.png` 4개 및 `outputs/augmentation.csv`

**검증 범위의 한계:** ZIP에는 원본 이미지 및 원본 `../data/manifest.csv`가 포함되어 있지 않다. 따라서 원본 대비 밝기 변화, 원본 파일 해시 재계산, 원본의 비변경 여부, 전체 valid/test 건수와 누락 여부는 독립적으로 검증할 수 없다.

## 3. 처리 결과 상세

| 이미지 ID | Seed | 좌우 반전 | 밝기 β | 파일 저장 | 기준 PNG 비교 |
|---|---:|---|---:|---|---|
| `img_01` | 43 | 미적용 | -4 | 성공 | 일치 |
| `img_02` | 44 | 적용 | +13 | 성공 | 일치 |
| `img_03` | 45 | 미적용 | +9 | 성공 | 일치 |
| `img_04` | 46 | 미적용 | -12 | 성공 | 일치 |

**요약 해석**

- `img_02`만 좌우 반전이 적용되었다. 4개 표본에서 실제 반전률이 25%라는 사실이 코드의 설정 확률 50%와 모순되지는 않는다. 소표본의 관측 비율일 뿐이다.
- `img_02`(+13), `img_03`(+9)은 밝기 증가 설정, `img_01`(-4), `img_04`(-12)는 밝기 감소 설정이다.
- 모든 증강 결과는 **320×240 픽셀**이며, 열기·디코딩에 성공했다. `uint8` 값을 PNG로 기록한 3채널 컬러 이미지다.
- 출력 폴더의 PNG 4개가 `expected/`의 대응 PNG와 각각 **SHA-256 해시까지 일치**한다. 즉 파일 내용이 동일하다.

## 4. 품질 검증 및 합격 기준

| 검증 항목 | 검증 방식 | 결과 | 판정 |
|---|---|---|---|
| 파일 생성 | `outputs/` PNG 4건 실존 | 4건 확인 | **PASS** |
| 저장 상태 | CSV `saved=True` 및 PNG 디코딩 | 4/4건 | **PASS** |
| 실행 재현 산출물 | PNG를 `expected/`와 바이트 비교 | 4/4건 동일 | **PASS** |
| 설정값 및 이력 | CSV의 Seed/Flip/Beta와 기준 CSV 비교 | 기록값 전부 일치 | **PASS** |
| 데이터 분할 준수 | 결과 CSV의 `split` 확인 | train 4건, 그 외 0건 | **부분 PASS** |
| 결과 CSV 일치 | 기준 CSV와 필드 비교 | 출력 경로의 OS 구분자(`\` vs `/`)를 제외하고 동일 | **PASS** |
| 원본 데이터 무결성 | 기록된 `source_sha256`을 실제 원본과 재계산 | 원본 미제공 | **미검증** |
| 모델 성능 개선 효과 | 원본 학습 대비 검증지표 비교 | 학습/평가 실험 없음 | **미검증** |

**기준 CSV 차이:** `outputs/augmentation.csv`는 Windows 경로 구분자 `\`, `expected/augmentation.csv`는 `/`를 쓴다. 경로 표현 차이일 뿐, 해당 필드를 제외한 설정·상태·원본 해시 정보는 동일하다. 제품화 시 저장 경로 포맷을 표준화하는 것이 좋다.

| 우선순위 | 항목 | 영향 | 권고 조치 |

| P2 | 처리 성능 미측정 | 대량 데이터 처리 시 시간·디스크 비용 불명 | 처리 시간, 초당 이미지 수, 평균 파일 용량 측정 |

## 6. 다음 단계: 현업 적용 승인 전 검증 계획

1. **데이터 검증:** `manifest.csv` 원본과 실제 폴더를 대조해 train 4건, valid/test 2건인지 확인한다. 각 원본 SHA-256을 재계산하고 증강 전후 원본이 동일한지 검사한다.
2. **증강 품질 검수:** 각 샘플의 원본·증강 이미지를 쌍으로 비교하고, 라벨 의미 유지 여부와 심한 클리핑이 없는지 판정한다.
3. **모델 실험:** 증강 없이 학습한 Baseline과 동일 조건에서 증강을 적용한 실험군을 비교한다. 분류라면 Accuracy 외 Precision/Recall/F1 및 클래스별 오류를 함께 본다.
4. **운영 안정화:** 입력 파일 오류·저장 실패·중복 ID를 예외 처리하고, 파이프라인 실행 버전, 처리 소요 시간, 해시 및 실패 건수를 로그로 남긴다.
