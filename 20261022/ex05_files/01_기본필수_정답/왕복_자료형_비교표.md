# CSV·JSON 왕복 비교 · 강사용 예시

| 값 | 저장 전 | 파일 표현 | 다시 읽기와 확인 |
|---|---|---|---|
| run_id `001` | 문자열 | CSV의 `001` | `dtype={"run_id":"string"}`으로 읽어 앞자리 0을 보존한다. |
| 날짜 NaT | datetime의 결측 | CSV의 빈 셀 | 날짜 변환 전에는 빈 측정으로 읽힌다. `to_datetime` 후 NaT인지 비교한다. |
| latency NaN | float의 결측 | CSV의 빈 셀 | 숫자 열의 NaN으로 읽는다. 0으로 대체하지 않는다. |
| 요약 평균 결측 | NaN | JSON `null` | `json.loads`는 None으로 읽는다. 수치 열로 복원한 뒤 결측의 의미를 비교한다. |

CSV는 자료형을 완전히 보존하는 형식이 아니므로 ID와 날짜의 읽기 규칙을 지정한다. 표준 JSON에는 NaN·Infinity를 쓰지 않는다. JSON 파일의 문자열이나 소수점 마지막 자리가 아니라 값·행 순서·결측의 의미를 검사한다.

빈 파일·헤더만 있는 파일·필수 열 누락·잘못된 인코딩·손상 JSON은 의도된 오류 입력이다. 정상 데이터로 고치는 대신 명확히 실패하고 기존 결과를 보존하는지 확인한다. 세부 실행 결과는 단계별 `테스트_기록.md`에 있다.
