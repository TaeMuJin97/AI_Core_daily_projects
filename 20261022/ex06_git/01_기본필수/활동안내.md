# 실습06 · Git · 기본필수

**역할 폴더에서 아래 프로젝트로 이동합니다. 개인 홈·상위폴더에서 init하지 마세요.** 이미 이 프로젝트에 .git이 있다면 재초기화하지 않고 status/log를 확인한 뒤 이어서 합니다. 이미 상위 폴더가 Git 저장소인 환경에서는 별도 연습폴더로 day4_eda만 복사해 수행합니다.

```text
cd "ex07_project/01_기본필수/day4_eda"
git init -b main
git config user.name "Student"
git config user.email "student@example.com"
git branch --show-current
git status --short
```
이름·이메일은 커밋 메타데이터로 남습니다. 공유에 사용할 본인 값을 쓰되 전역(--global) 설정은 변경하지 않습니다. Git 2.28 미만이라 -b가 안되면 강사에게 확인합니다.

## 기본필수: 의미가 다른 커밋 2개
프로젝트의 README.md/.gitignore 초안을 읽은 후 첫 커밋을 남깁니다.
```text
git add README.md .gitignore
git diff --cached --stat
git commit -m "docs: add project guide"
```
VS Code에서 README에 **실제 사용 환경·실행 명령**을 보완하고 저장합니다. 빈 커밋으로 수를 채우지 않습니다.
```text
git diff
git add README.md
git diff --cached
git commit -m "docs: explain local run command"
git log --oneline -2
git status --short
```
이 배포본에는 main.py/data/eda/tests도 이미 있으므로 첫 두 커밋 후 `??`로 나타날 수 있습니다. 이는 소스가 아직 추적되지 않은 정상 상태이며 빈 출력이라고 예상하면 안 됩니다. 이때 코드는 아직 미완성이어도 됩니다. 07/08에서 구현한 뒤 필요한 소스를 추가로 커밋합니다.

## 08 제출 직전: 소스·작은 합성 원본·보고서 포함
실제로 파일이 존재하고 미구현 TODO를 해결했는지 먼저 확인한 뒤 필요한 파일만 스테이징합니다.
```text
git add main.py support.py eda data reports tests requirements.txt README.md .gitignore
git diff --cached --stat
git commit -m "feat: complete reproducible EDA project"
git status --short
git log --oneline --all --decorate
```
PNG와 out 결과를 저장소에도 포함할지는 강사의 지침을 따릅니다. 포함한다면 검수한 작은 합성 결과만 `git add out` 후 추가로 커밋합니다. 결과를 추적하지 않는 정책이면 .gitignore에 out/을 추가하되 제출 ZIP에는 요구된 결과를 남깁니다. 모든 파일을 무작정 add하지 않습니다.

.gitignore는 이미 커밋한 비밀정보의 과거 이력을 지우지 않습니다. .venv·캐시·.env·개인정보는 제출하지 마세요. 네트워크·push·강제 reset·clean은 필요하지 않습니다.

## 확인 (역할 폴더로 돌아온 후)
```text
python tools/check_git.py --project "ex07_project/01_기본필수/day4_eda" --level basic
```
명령/예측/실제 결과는 명령_기록.md에 기록합니다. 자동 읽기 검사로 커밋 수·브랜치·제외 파일을 확인하고, 변경의 의미는 짝과 함께 검토합니다.
